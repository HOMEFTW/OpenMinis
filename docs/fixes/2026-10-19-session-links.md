# 会话链接与新对话读取

## 目标与实施顺序

用户可在已有会话复制 `minis://session/<id>`，在新对话输入“阅读对话 <链接>，帮我……”；AI 能按链接读取本机原会话的可见历史，并在新对话处理任务。明确要求联系原会话时，也可直接以链接为通信目标。

1. 共用链接生成与解析：兼容已有 ID，拒绝其他协议、文件预览路径和非法引用。
2. 聊天菜单及会话列表长按菜单增加复制入口；未发送的新对话不因复制而落库。
3. 现有 `session_message` 增加只读 `history` 操作，长消息和会话均可分页；`send` 接受链接，保留接收授权与防循环规则。现有 CLI 读取入口也兼容链接。
4. 更新工具说明和系统提示；历史是参考资料，不自动合并消息、复制附件或触发目标模型。

## 验收

- 链接复制、ID 往返、中文及转义 ID、非法和跨应用链接。
- 读取到原会话问题和回答；原会话未开启 AI 消息接收时仍可只读，读取不修改任一会话或启动任务。
- 长消息在固定输出预算内连续分段，空白／内部消息不会导致分页偏移错误；不存在或已删除的会话明确报错。
- 使用链接发送仍必须通过目标接收授权，旧通信记录 `read` 操作保持原义。
- 用项目构建脚本运行回归与 APK 构建；真机和真实模型联调另行说明。

## 实现结果

- 聊天右上角菜单和会话列表单项长按菜单均有带图标的“复制会话链接”。可用条件依据已保存会话；实际写入剪贴板前再查数据库，失效时提示失败，不创建空会话。
- `SessionLink` 统一生成和解析 `minis://session/<id>`，支持原始 ID、复制链接、Markdown／尖括号包装及编码字符；排除其他协议、资源文件路径、附加查询和非法路径。
- `session_message history` 直接只读聊天仓库，不初始化邮箱或运行目标 AI。系统提示明确识别“阅读对话 <链接>，帮我……”并在当前对话继续；原 `read` 保持通信记录查询含义。
- 读取默认 20 行、最多 50 行、总文字预算 32,000 字符；逐行加载，到预算即停。每个 JSON 文字块最多 1,000 字符，保持 Unicode 完整，输出将续读元数据放在正文前，支持落盘后的默认文件窗口回读。
- 续读同时携带 `next_offset`、`next_text_offset` 和 `next_message_id`。原消息删除或位置变化时明确报告历史已改变，可从头重读，避免在另一条消息的中途继续。
- 链接通信仍经原 `SessionMailbox` 接收授权、来源／目标存在性及防循环检查。读取不自动共享图片、文件或完整工具日志；完整工具详情沿用既有 CLI。
- 既有 `minis-sessions-cli messages --id` 同时接受链接和 ID，缺失的本机会话返回 `NOT_FOUND`，与空会话区分。
