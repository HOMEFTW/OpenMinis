# Android 启动与返回修复（2026-09-14）

后续日常使用增强更新了启动候选规则，详见 [日常使用增强](android-daily-use.md)。

## 启动规则

沿用设置 → 外观 → 启动会话的选项：

- 自动（默认）：最后查看的会话在 15 分钟内则打开它，否则新建草稿；没有查看记录时兼容最近更新的会话，没有历史则进入列表。
- 最后查看的对话：优先打开实际最后查看的会话；目标删除后回退到最近更新的会话。
- 新对话：新启动时打开空白草稿。
- 首页：进入会话列表。

尚未配置服务商且没有历史时先显示首页；分享输入和崩溃保护有原有的专门处理。
切到后台再回来、从文件选择器返回，以及系统恢复已有页面时，保留当前页面，不重复应用启动选项。

## 原因与修改

启动导航把 chat 放在 sessions 上方，但手机聊天内部的自适应布局又包含列表历史，形成两份会话列表。手机现在使用单份列表/详情选择状态；外层打开的聊天将返回栈收拢为唯一的 sessions，快捷入口也采用相同规则，避免露出底层列表曾经打开的旧聊天。聊天内切换或新建不增加返回层数。列表的可保存状态继续保留。

Activity 重建时，NavController 和 Compose 已恢复页面，启动调度不再重复导航。快捷入口生成的草稿 ID 使用可保存状态，防止重组重新生成。移除 onStart 中无条件尝试新建的逻辑，避免从系统界面回来丢失当前上下文。

## 装机验收（本机无设备，尚未执行）

1. 分别设置四种启动选项，彻底关闭后重新进入，核对上述规则。
2. 默认自动恢复聊天后按返回：只出现一次列表；再按返回离开应用。
3. 列表打开会话 A，再新建或切换会话 B，返回应直接到列表，不逐个返回旧会话。
4. 从快捷方式新建聊天，返回列表后再次返回应离开，不重新显示快捷聊天。
5. 聊天输入草稿，切后台、打开附件选择器后取消，当前聊天和输入应保留。
6. 设置页或聊天页旋转屏幕、开启“不保留活动”后切换应用，恢复后不执行一次新的启动跳转。
7. 打开模型菜单、思考菜单、附件弹窗，返回应先关闭弹层；列表滚动位置返回后应保留。

普通 JVM 单测不覆盖系统返回手势和 Compose 生命周期，构建成功不能替代以上验收。
