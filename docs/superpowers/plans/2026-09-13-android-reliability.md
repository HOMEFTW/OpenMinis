# Android 可靠性修复与体验优化实施方案

**目标：** 修复体检的 F01–F08，增加会话成果入口、服务商调用自检和任务轮数预算提醒，交付可安装 APK。
**架构：** 延用现有 Kotlin / Compose / Room / PRoot 分层；提取小型可单测策略，复用现有文件预览与模型工厂。保留现有用户修改，不改 iOS。用户已授权先制定方案后执行；本轮不提交或推送。

## 实施清单

- [x] A. 模型兼容与自检（F01）：Anthropic 的 OAuth 标识只在 OAuth 分支读取；更新 OpenAI SSE 测试；在 ProviderDetailScreen 增加“测试调用”，明确会发出一次简短请求，展示耗时/错误并支持取消。使用所选服务商的文本模型，复用实际工厂与凭据；不对用户接口自动运行测试，不自动调用生图。验收：API Key 无 OAuth 配置正常、流式测试通过、自检选项可编译并有状态管理。
- [x] B. 凭据与诊断（F03/F08）：EncryptedPrefsFactory 不再删除共享主密钥或其他库；加密失败保留原文件、使用进程内临时存储并可见提示。旧明文 fallback 只有成功迁入加密存储后清理。日志落盘及分享前脱敏，覆盖命令内授权头、Cookie、已知密钥及签名 URL。验收：故障策略/内存存储/脱敏用合成数据测试，不读取真实凭据。
- [x] C. 任务终态与定时记录（F05/F06）：当前执行有独立运行标识与成功/失败/取消/预算停止结果；HeadlessChatRunner 不再仅靠 isStreaming 判断成功或拿旧回复。未启动和调度交接异常均留下失败记录，只有成功才 ok=true。验收：成功、错误、取消、未启动、超时、旧消息场景的针对性测试。
- [x] D. 会话隔离与产物（F02/F04）：输入 JSON、系统文件、参考图与输出均传 sessionId，不使用可变全局会话状态；统一 text/usage/media_files 结果保存，JSON 为清单、全部附件落盘。验收：A/B 同名文件隔离、全局共享不变；文本/JSON/媒体输出、多附件和失败场景测试。
- [x] E. 终端保真（F07）：修正回车覆盖保留尾字符，ANSI 不计可见列，保留合法 null 与首尾空白，保留明确长度截断。验收：现有失败测试和新 null/ANSI 回归通过。
- [x] F. 会话成果：聊天菜单增加“任务成果”，集中列出当前会话 attachments/workspace 的文件，显示类型/大小，复用预览与分享；限制扫描并防止越出当前会话，后台读取，支持刷新。验收：目录筛选/排序/范围测试和 Android 编译。
- [x] G. 任务预算：默认沿用现有 200 轮上限，允许在聊天内调整本机任务轮数上限；接近上限和重试时提示，达上限保留继续入口。不伪造金额估算，不增加自动付费探测。验收：配置边界/默认值/预算状态与运行上限一致。
- [x] H. 集成验收：审查跨模块接口，完整 Android 单测、APK 构建、ZIP/原生依赖/签名检查；更新结果说明并输出新版 APK。

## 完成标准与边界

每组业务逻辑使用针对性回归测试；出现失败先确认原因，不删断言掩盖缺陷。重用本机已有构建方法。没有连接设备时，明确标注后台/Keystore/Compose/系统分享及真实接口仍需真机验收；不将编译或单测当作真机通过。成果页、自检和预算均是现有应用内的增量入口，不扩展成新的云服务或自动化平台。
